ADR-0003: CSV parser shape decision matrix

Companion to ADR-0003. The order-routing stage turns one UDP datagram into one typed request. The sample wire protocol has three markers and fixed field counts.

Assumptions

  • Closed grammar: the protocol defines N, C, and F.
  • Fixed shape: each marker has a fixed field count.
  • Well-formed fixtures: scenario rows follow the documented command shapes.
  • Hot path: order routing sits on the packet-processing path.
Criterion A. Fixed-shape string_view split Switch on marker, split expected fields, parse into strong request types. B. General tokenizer Expose a local token stream over the datagram. C. CSV/parser library Use a parser library for CSV records.
Protocol fit Direct match for fixed tuples. Works, but models more flexibility than the protocol has. Brings dialect behavior the protocol does not define.
Allocation Datagram slices are cheap; current field collection can allocate and can be swapped later. Can be allocation-free. Depends on parser behavior.
Reader clarity Code mirrors the wire record shape. Reader must follow cursor state. Parser hides mechanics but raises dialect questions.
Error path Helpers assert protocol preconditions; the decoder boundary keeps a result-returning API. Can return local token diagnostics. Library errors still need domain translation.
Dependency surface No parser dependency. No parser dependency. Adds dependency weight for unused CSV features.
Future grammar growth Quoted or variable-width records need a new parser decision. Can absorb moderate growth. Best if the protocol becomes full CSV.

Decision

Decision: A. Fixed-shape string_view split. The parser follows the sample wire protocol directly. The result-returning boundary stays in place for future structured parse rejection.
