ADR-0004: order-book data structure decision matrix

Companion to ADR-0004. The matching engine needs per-symbol books that preserve price-time priority, expose top-of-book aggregates, and support cancellation by (user, user_order_id).

Assumptions

  • Behavior first: the initial structure should make matching semantics easy to verify.
  • Optimization next: the optimized structure should target direct cancellation and allocation control.
  • Sparse prices: the engine cannot reserve a fixed tick range or depth distribution.
  • Local swap: storage changes should stay inside the matching-engine module.
Criterion A. Sorted maps of vectors Price map to FIFO vector at each level. B. Intrusive lists + pool Price map to intrusive FIFO lists of pool-owned order nodes. C. Preallocated vectors + tombstones Bounded per-level arrays with inactive entries. D. Paged order blocks Pool-owned fixed-size blocks chained per price level.
Behavior readability Standard containers make price-time priority visible. Readable, but intrusive hooks and ownership matter. Readable until tombstone cleanup enters the path. Storage mechanics dominate the review.
Cancel latency Scans resting orders. Identity index plus intrusive unlink gives direct cancellation. Direct handle can mark a tombstone. Direct handle works, with block accounting overhead.
Placement allocation New levels or vector growth can allocate. Pool-owned nodes can avoid per-order heap allocation. Safe operation depends on capacity assumptions. A block pool can bound allocation.
Sparse prices Creates levels only when prices appear. Creates levels only when prices appear. Reservation either overallocates or risks overflow. Works if the block pool is sized for total active depth.
Sweep locality Vectors are contiguous. Pointer chasing can cost cache locality. Contiguous scans suit hardware prefetch. Mostly contiguous within blocks.
Test surface Mostly behavior tests. Needs pool, hook, pointer, and index consistency tests. Needs tombstone and compaction tests. Needs iterator, block reclamation, and accounting tests.
Iteration fit Best behavior-first step. Best optimized step. Capacity assumptions make it a poor intermediate step. A later candidate if sweep locality dominates.

Decision

Decision: A for the behavior-first iteration, then B for the optimized iteration. Sorted maps of vectors made the matching contract visible. The optimized book uses pool-owned nodes and intrusive per-level lists so cancellation is direct and resting order addresses stay stable.
